## Part I — Business description

### What this is

The application you actually run: a browser-based TRICC authoring tool that opens a project folder
on your computer, with no server, no account and no sign-in.

It is deliberately thin. Every screen it shows comes from `@tricc/editor`; every rule it enforces
comes from `@tricc/core`. What it contributes is the wiring: where projects live, who you are, and
the surrounding chrome.

That thinness is the point — it is the proof that a hosted version is a matter of different wiring
rather than a second product.

### Your work stays on your machine

A project is a folder you open and save, like a document.

- Nothing leaves your computer unless you send it. Guidelines are frequently unpublished ministry
  content, and this removes the question of where it is stored.
- It works offline, including in a workshop with no connectivity.
- Projects sit in git alongside everything else, so guideline changes are reviewed the way code is.

The application saves continuously to the open folder. Where a browser cannot write to a folder
directly — Firefox and Safari do not support it — it keeps your work in browser storage and you
save by downloading. You are told which mode you are in, plainly and persistently, rather than
discovering it when something is missing.

### No accounts

There is nobody to log in as. You set a display name in Preferences, which is used to record who
authored what, and — if you later use a hosted version — to show your presence to collaborators.
The prototype's user-management screen is removed; it described a feature that cannot exist here.

### Replacing the prototype

The existing application is built on Create React App, unmaintained since 2023, and its data model
cannot represent what TRICC needs — most fundamentally it has no field for a node's *name*, the
identifier every expression in a guideline refers to. Its editor layout and node visuals are worth
keeping. Its foundation is not.

## Part II — Technical specification

### 1. Toolchain

| Concern | Choice | Why |
|---------|--------|-----|
| Build | **Vite** (latest stable) + `@vitejs/plugin-react` | Replaces `react-scripts` 5, unmaintained and pinned to a Babel/Jest stack that fights ESM-only dependencies. |
| Language | **TypeScript 5.x**, `strict: true`, project references | Prototype is on 4.9 with strictness off. |
| UI | **MUI** (latest stable) | Continuity with the prototype. |
| Routing | **React Router 6** | Continuity. |
| Unit | **Vitest** | Shares Vite's transform pipeline; one build config. |
| E2E | **Playwright** | Required for the File System Access API and drag-based graph interaction; jsdom can exercise neither. |
| Lint/format | ESLint 9 flat config + Prettier | Neither exists today. |

Peer dependencies of `@tricc/editor` (React, MUI, `@xyflow/react`, CodeMirror) are resolved here,
so the app owns exactly one copy of each.

### 2. Structure

```
apps/local/src/
├── main.tsx          # adapter composition, runtime provider
├── routes/           # project list, project workspace, preferences
├── chrome/           # app bar, storage-mode indicator, about
└── preferences/      # local preference store (display name, theme, language)
```

No domain logic. An ESLint rule restricts imports here to `@tricc/*`, React and routing — logic
that appears in `apps/local` is logic a hosted shell would have to reimplement, so it is a build
error rather than a review comment.

### 3. Local adapters

`@tricc/adapters-local`, each passing the conformance suite in `@tricc/core/testing`.

#### 3.1 Persistence

Two implementations, selected by capability detection at startup:

- **`FileSystemPersistence`** (Chromium) — `showDirectoryPicker()`; the handle is kept in
  IndexedDB so reopening restores the project without a second prompt. Writes only changed files,
  which is what keeps git history clean and continuous saving cheap. `watch` polls modification
  times on window focus. Declares `{ canWatch: true, canWriteIncrementally: true }`.
- **`DownloadPersistence`** (Firefox, Safari) — project held in the document and mirrored to
  IndexedDB; saving downloads `project.tricc` (ZIP). Opening accepts a ZIP or a multi-file
  selection. Declares `{ canWatch: false, canWriteIncrementally: false }`.

The storage mode is shown persistently in the app bar. A user in download mode must know before
they close the tab, not after.

#### 3.2 Catalog

`LocalProjectCatalog` — recently-opened projects, stored as IndexedDB directory handles with
permission re-request on reopen. In download mode, entries reference IndexedDB-held projects.

#### 3.3 Identity

`LocalIdentity` — one identity from local preferences (display name, optional email, presence
colour), granting every capability except `project.share`. No authentication.

A read-only toggle is offered in the UI, dropping `project.write` for the session. It costs
nothing, it makes review-without-touching real, and it exercises the capability path continuously
rather than leaving it untested until a hosted shell needs it.

#### 3.4 Collaboration

`IndexedDbCollaboration` — wraps `y-indexeddb`. Provides local durability and the offline log
(`20260825-document-model.md` §7). No network. Awareness is a single local participant.

### 4. Saving, recovery, external change

Behaviour is defined in `20260825-document-model.md` §7; the app supplies the interface around it.

- Continuous save, debounced 2 s, plus on route change and `visibilitychange`.
- Save state is always visible: saved / saving / unsaved / error, with the last-saved time.
- On startup, an IndexedDB log newer than the files triggers a **recovery prompt** showing both
  timestamps. Never automatic, never silent.
- `beforeunload` guard while unsaved changes exist.
- External file change on focus prompts reload-or-keep. Silently overwriting a colleague's `git
  pull` is the failure most likely to make people distrust the tool.

The prototype persists to `localStorage` — synchronous, roughly 5 MB, and it throws on quota. A
realistic guideline with images exceeds it. IndexedDB throughout.

### 5. Screens

| Route | Content |
|-------|---------|
| `/` | Project list: recent projects, open folder, create, import `.tricc` |
| `/project/:ref` | **Project overview** — the layer -1 surface (`20260826-project-and-interventions.md` §4) |
| `/project/:ref/activity/:id` | Workspace: five-level navigator, `@tricc/editor` canvas, validation panel |
| `/project/:ref/settings` | Metadata, interventions, languages, terminology configuration |
| `/project/:ref/concepts` | Concept browser (`20260825-terminology.md`) |
| `/project/:ref/concepts/:system/:code` | Concept page — the CQL editor's **(i)** target |
| `/preferences` | Display name, theme, UI language, storage mode |

`src/pages/UserAccount.tsx` is deleted. `ProjectDashboard.tsx`, `ProjectSettings.tsx` and
`TerminologyServer.tsx` are replaced by editor-package components with app-level routing.

### 6. i18n

`react-i18next` from the start; English resources only in v1. Content localization is a document
concern (`20260825-project-format.md` §6); this covers UI chrome, so adding a locale is a resource
file rather than a refactor.

### 7. Export

Export produces the project files, or `project.tricc`, or the generated CQL libraries and FHIR
CodeSystem for review. Blocked while validation errors or CQL profile violations exist, with the
blocking issues listed and linked.

`tricc_oo` conversion is **not** run from the app — it is Python. Export produces the input
`tricc_oo` consumes (`20260825-tricc-oo-interop.md`).

### 8. Testing

Package-level testing is specified in `20260825-library-architecture.md` §8. This app adds:

**Adapter unit tests** — the conformance suite against both persistence implementations, plus
FSA-specific behaviour (handle persistence, permission re-request, incremental write scoping) with
a fake file system.

**E2E journeys** (`e2e/`, Chromium and Firefox):

1. Create a project, add an intervention and an activity, save, reopen — positions preserved.
2. Build a branching activity, set a CQL relevance through the concept picker, export.
3. Import a `tricc_oo` YAML fixture, edit one label, re-export; the diff shows only that label.
4. Continuous save, then simulated crash — recovery prompt restores the work.
5. Validation surfaces a `goto` to a deleted activity and blocks export with a usable message.
6. Firefox: download-mode indicator visible; ZIP round-trip works.
7. Read-only toggle: editing affordances disappear and the document rejects mutation.

Each journey is independent — no shared mutable state, no ordering dependency.

**Contract tests against `tricc_oo`** — the category that catches the failure that matters: the
app saving something `tricc_oo` cannot read.

- A CI job with Python and `../tricc_oo` installed runs `tests/build.py` over exported projects,
  asserting exit status and expected artefacts.
- Pinned to a `tricc_oo` commit, bumped deliberately, so a Python-side change breaks this repo's
  CI loudly rather than breaking authors quietly.
- Until `20260825-tricc-oo-interop.md` phase 1 lands, it asserts only against the `YamlStrategy`
  subset that already parses.

Explicitly rejected: snapshot tests of rendered components. They pass by being regenerated and
catch nothing.

### 9. CI

GitHub Actions, on push and PR, Turborepo-cached:

1. `typecheck` — `tsc --noEmit` across the workspace
2. `lint` — ESLint + Prettier + the import-restriction rules (§2, and `core`/`cql` React ban)
3. `test` — Vitest per package, coverage thresholds enforced
4. `build` — every package + the app; bundle-size regression > 10% fails
5. `api` — api-extractor report diff, `publint`, `attw`
6. `changeset` — required for changes under `packages/`
7. `test:e2e` — Playwright, Chromium + Firefox, traces on failure
8. `test:contract` — §8, non-blocking until interop lands

### 10. Migration from the prototype

Ported into `@tricc/editor`: `ActivityEditor` layout, `flow-nodes/*` visuals, `ConceptSelector`
interaction shape, `MainLayout` chrome.

Deleted: `src/types/index.ts`, `src/utils/export-generators.ts`, `triccSerializer.ts`,
`triccValidator.ts`, `undoManager.ts`, the three undo hooks, `useProject.ts`,
`pages/UserAccount.tsx`, `REQUIREMENTS_ARCHITECTURE.md`, `USER_DOCUMENTATION.md`, `.cline`.

The repository currently has **no commits at all**. First action on approval: commit the prototype
as-is on a `prototype` branch so the reference is preserved, then build on `main`.

### 11. Acceptance criteria

- [ ] `apps/local` contains no domain logic, enforced by lint.
- [ ] Both persistence adapters pass the conformance suite.
- [ ] A project saves to a real directory in Chromium and survives reload.
- [ ] Firefox gets a working download path with a visible, persistent mode indicator.
- [ ] Simulated crash mid-edit recovers from the local log.
- [ ] External on-disk change prompts rather than being overwritten.
- [ ] The read-only toggle prevents mutation at the document layer, not only in the UI.
- [ ] No account, profile or authentication surface exists anywhere in the app.
- [ ] Export is blocked while errors or profile violations exist, and says why.

### 12. Implementation phases

1. Vite scaffold in the workspace; TS strict; lint; Vitest; Playwright; CI skeleton.
2. Local adapters against the conformance suite.
3. Runtime composition, routing, chrome, storage-mode indicator.
4. Save orchestration, recovery, external-change handling.
5. Preferences and i18n scaffolding.
6. Export flows.
7. Contract-test harness.
